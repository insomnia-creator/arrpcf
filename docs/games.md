Discord's desktop client detects games by scanning the process table and comparing
executables against its *detectable* application database. arrpcf does the same on
macOS: it walks processes, matches them against the same database, and publishes an
activity with the Discord application id — no game integration required.

Detection is on by default and can be disabled with `--no-process-scanning`.

## Scanning

| Step | What happens |
| --- | --- |
| List processes | `proc_listpids(PROC_ALL_PIDS)` from `libproc` |
| Resolve executables | `proc_pidpath(pid)` returns the full path of the running binary |
| Read arguments | `sysctl(KERN_PROCARGS2)` returns `argc`/`argv`; arrpcf joins `argv[1..]` |
| Match | compare against the detectable database (below) |
| Publish | a synthetic `SET_ACTIVITY` whose `application_id` is the Discord app id |

Scans run every 5 seconds (`--scan-interval`), starting immediately at launch.

<div class="note">
<code>proc_pidpath</code> and <code>KERN_PROCARGS2</code> only expose processes of the
same user (all users when running as root). That is exactly the set you can launch
yourself, which is what matters for game detection.
</div>

## Matching rules

An executable matches a database entry when any of these applies, in this order:

1. **Basename entries** — database names prefixed with `>` (for example `>hl2_osx`,
   `>java`) must equal the last path segment exactly. These entries also require an
   `arguments` substring, which is why `hl2_osx -game tf` becomes Team Fortress 2 and
   `hl2_osx -game garrysmod` becomes Garry's Mod.
2. **Path suffixes** — the database name is compared against every suffix of the
   process path. For `/Applications/Brawlhalla.app/Contents/MacOS/Brawlhalla` the
   suffixes include `brawlhalla`, `macos/brawlhalla`,
   `contents/macos/brawlhalla`, `brawlhalla.app/contents/macos/brawlhalla`, and so on.
   Each suffix is also compared with 64-bit markers removed: the first `64`, `.x64`,
   `x64` or `_64`. This mirrors arRPC and covers databases that store paths such as
   `osx64/dota2.app`.
3. **Bundle names** — for `.app` entries without a slash, the bundle directory may
   appear anywhere in the path. macOS reports
   `/Applications/Brawlhalla.app/Contents/MacOS/Brawlhalla` for a running app, so
   `brawlhalla.app` matches through the `/brawlhalla.app/` segment.

If an entry also specifies `arguments`, the joined command line must contain that
substring.

Examples:

| Process path | Database entry | Result |
| --- | --- | --- |
| `/Applications/Brawlhalla.app/Contents/MacOS/Brawlhalla` | `brawlhalla.app` | match (bundle) |
| `/Applications/Dota 2/osx64/dota2.app/Contents/MacOS/dota2` | `osx64/dota2.app` | match (suffix) |
| `/tmp/hl2_osx` with `-game tf` | `>hl2_osx` + `-game tf` | match |
| `/tmp/hl2_osx` with `-windowed` | `>hl2_osx` + `-game tf` | no match (arguments) |
| `/usr/bin/java -jar … net.minecraft.client.main.Main` | `>java` + `net.minecraft.client.main.Main` | match |

Only darwin executables from the database are considered, so Windows or Linux
executable names that happen to exist on macOS cannot produce false positives.

## The detectable database

Discord publishes the list at
[`https://discord.com/api/v9/applications/detectable`](https://discord.com/api/v9/applications/detectable).
The full file is about 11.6 MB and contains every platform, icons, SKUs and themes.

arrpcf embeds a reduced copy: the 63 macOS applications, 7.3 KB of JSON, generated by
`tools/gen_detectable.py`. To use Discord's current full file instead:

```sh
curl -o detectable.json https://discord.com/api/v9/applications/detectable
arrpcf --detectable ./detectable.json
```

The full file is parsed and filtered at startup (about 50 ms), so results are the
same — this is only about keeping the binary small.

Regenerate the embedded copy after a database update:

```sh
python3 tools/gen_detectable.py     # downloads the current database
make                                # rebuild with the new subset
```

## Lifecycle

- **First sighting** — the log prints `detected game! <name>` and the activity's
  `timestamps.start` is fixed to that moment.
- **Every scan** — the activity is re-published. This is intentional: if Discord
  connects later, the bridge replay gives it the current game.
- **Disappearance** — the log prints `lost game! <name>` and an `activity: null`
  message with the last pid is published.
- **Restart** — a new `start` timestamp is used.

A scan reports at most one activity per Discord application id, even if several
processes share an engine or executable.

## Debugging

```sh
arrpcf --scan-once                 # one scan, printable result
arrpcf --scan-once --debug         # plus the database that was loaded

arrpcf --detect-path "/Applications/Brawlhalla.app/Contents/MacOS/Brawlhalla"
arrpcf --detect-path "/Applications/Dota 2/osx64/dota2.app/Contents/MacOS/dota2"
```

Pretend specific processes exist — useful to test detection without installing games:

```sh
ARRPCF_FAKE_PROCESSES="/Applications/Brawlhalla.app/Contents/MacOS/Brawlhalla|4242" arrpcf --scan-once
```

For detection *and* loss, point arrpcf at a file that is re-read on every scan:

```sh
echo "/Applications/Brawlhalla.app/Contents/MacOS/Brawlhalla|4242" > /tmp/fake.txt
ARRPCF_FAKE_PROCESSES_FILE=/tmp/fake.txt arrpcf --scan-interval 1
: > /tmp/fake.txt     # next scan publishes an activity: null
```

## Games Discord only lists for Windows

Some titles run on macOS but only ship a Windows executable in Discord's database,
so no process can match. LÖVE-based games are the usual case: Balatro runs the
engine binary `love` inside `Balatro.app/Contents/MacOS/`, while Discord's entry is
only `balatro/balatro.exe` for `win32`.

Add the bundle name to a custom database and run with `--detectable`:

```sh
curl -o ~/detectable.json https://discord.com/api/v9/applications/detectable
python3 - <<'PY'
import json, os, pathlib
path = pathlib.Path(os.path.expanduser("~/detectable.json"))
db = json.loads(path.read_text())
for entry in db:
    if entry.get("name", "").lower() == "balatro":
        entry.setdefault("executables", []).append({"name": "balatro.app", "os": "darwin"})
path.write_text(json.dumps(db, separators=(",", ":")))
PY
arrpcf --detectable ~/detectable.json
```

Matching `Balatro.app` rather than `love` keeps other LÖVE games from being
identified as Balatro. To keep the override, add `--detectable <file>` to the
LaunchAgent's `ProgramArguments`. The downloaded database is a snapshot; re-run the
patch when Discord adds new games.

## Limits

- **Permissions.** Processes started by another user are not visible; run arrpcf as the
  same user as the game (a LaunchAgent is ideal).
- **Sandboxing.** A sandboxed App Store build of a helper cannot inspect other
  processes. Use the CLI or a LaunchAgent.
- **Unknown games.** Games missing from Discord's database are not detected, even if
  they support Rich Presence natively — those should connect over IPC/WebSocket and
  report their own activity.
- **Wrappers.** Titles running inside Wine, CrossOver, Parallels or a remote stream
  expose a wrapper path; matching only works if that path appears in the database.
- **Renamed bundles.** Renaming `Foo.app` changes the path, so entries matched by
  bundle name stop matching (suffix matches unaffected).
